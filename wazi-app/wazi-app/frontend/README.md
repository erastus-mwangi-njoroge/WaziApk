# WAZI web — Angular + Firebase

This folder is **not** a full Angular CLI project (no `angular.json` /
`package.json` / `tsconfig.json`) — those are best generated by the Angular
CLI itself so they match whatever Angular version you have installed,
rather than hand-written and risking going stale. What's here is the real
application source: every component, service, and the global stylesheet,
ready to drop into a freshly-scaffolded project.

The app talks directly to Firebase (Auth, Firestore, Storage) — there's no
custom backend server for the web app anymore.

## 1. Scaffold a fresh Angular project

```
npm install -g @angular/cli   # if you don't have it already
ng new wazi --standalone --routing --style=scss --ssr=false
```

Requires **Angular 17 or later** (CLI 17–19 generate the `app.component.ts` this README refers to; CLI 20+ renames it to `app.ts`, so use `npx @angular/cli@19 new …` if you hit that) (this app uses the `@if` / `@for` /
`@switch` control-flow syntax and signals). When prompted, keep the
defaults — standalone components, routing enabled, SCSS.

## 2. Copy this source in

From this `frontend/` folder, copy everything under `src/app/` and
`src/environments/` into the equivalent folders of your new `wazi/`
project, **overwriting** the CLI's generated `src/app/app.component.ts`,
`src/app/app.routes.ts`, and `src/environments/*` (keep everything else —
`app.config.ts`, `main.ts`, `index.html`, `angular.json`, etc. — as the CLI
generated them).

Then replace the CLI's generated `src/styles.scss` with this folder's
`src/styles.scss` (the design system/tokens for the whole app).

```
cp -r frontend/src/app/*        wazi/src/app/
cp    frontend/src/environments/* wazi/src/environments/
cp    frontend/src/styles.scss    wazi/src/styles.scss
```

## 3. Add the Firebase package and the fonts

```
cd wazi
npm install firebase
```

Open `src/index.html` and add these two lines inside `<head>`, right after
the CLI's default `<title>`/`<meta>` tags, so the Fraunces/Work
Sans/IBM Plex Mono fonts used throughout the app actually load:

```html
<link rel="preconnect" href="https://fonts.googleapis.com">
<link href="https://fonts.googleapis.com/css2?family=Fraunces:ital,opsz,wght@0,9..144,500;0,9..144,600;0,9..144,700;1,9..144,500;1,9..144,600&family=Work+Sans:wght@400;500;600;700&family=IBM+Plex+Mono:wght@400;500;600&display=swap" rel="stylesheet">
```

### Favicon

Copy `../branding/favicon.svg` into your project's static folder (`public/` on
Angular 18+, `src/assets/` on 17) and add inside `<head>` in `src/index.html`:

```html
<link rel="icon" type="image/svg+xml" href="favicon.svg">
```

The in-app logo is the `BrandLogoComponent` (`src/app/shared/brand-logo.component.ts`),
so nothing else is needed for the header and footer.

## 4. Set up the Firebase project

See `../firebase/README.md` for creating the Firebase project, enabling
Email/Password auth, Firestore, and Storage, and deploying the security
rules + Cloud Function. Once you have a Firebase web app registered, copy
its config object into **both** `src/environments/environment.ts` and
`src/environments/environment.prod.ts`.

## 5. Run it

```
ng serve
```

Open **http://localhost:4200**. Sign up as an owner, post a listing with a
premise photo, sign up as a tenant in another browser (or incognito
window), save it, set an alert, and watch the notification appear once the
Cloud Function runs.

## 6. Deploy

```
ng build
cd ../firebase
firebase deploy --only hosting,firestore,storage,functions
```

`firebase.json`'s `hosting.public` points at
`../frontend/dist/wazi/browser` — that's where `ng build` puts the output
for a standalone project built with the modern "application" builder
(Angular 17+ default). If your Angular version outputs somewhere else
(check the `dist/` folder after building), update that path in
`../firebase/firebase.json`.

## What's included

- Email/password sign in & sign up, choosing owner or tenant
- Browse & filter by town, house type, and max price, with the amenity-radar visual
- Listing detail with a photo gallery (premise photo first, then interiors), full amenity breakdown, "Contact owner", and save/favorite
- Owner: post a listing with a **required** whole-premise photo plus up to 8 optional interior photos, mark vacant/occupied, delete
- Tenant: saved homes, a preferences form that drives vacancy alerts, and a notifications tab (polled every 20s while the app is open, populated by the `notifyMatchingTenants` Cloud Function)

## Known limitations to fix as you take this further

- Firestore/Storage security rules here are reasonable for a first
  deployment but not airtight — see the comments in
  `../firebase/storage.rules` for the specific gap (upload isn't strictly
  tied to listing ownership) and consider tightening before wide launch.
- Deleting a listing doesn't delete its Storage images — add a Cloud
  Function on `onDocumentDeleted` if you want that cleaned up automatically.
- No email verification / password reset flow yet — Firebase Auth supports
  both, they're just not wired into the UI here.
